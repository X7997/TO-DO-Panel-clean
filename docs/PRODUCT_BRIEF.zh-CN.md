# TO-DO Panel：产品需求与创新点

> 本文把知识库中的 P35 项目卡片与当前实现整理成可供协作者理解的产品说明。它不是对早期提示词的逐字复刻；能力描述以仓库代码为准。

## 一句话定位

一个平时不占屏幕、只在桌面上有意唤醒的 Windows 开发者工作台：它把任务挂到真实项目上下文，允许 AI Agent 从命令行派活，并用可审查、可回收的方式整理构建产物。

## 为什么要做

开发工作常在代码仓库、模型目录、固件版本和多个 Agent 之间切换。传统待办窗口既脱离项目文件夹，又需要一直占着桌面；清理脚本则容易把稳定版、最新权重或固件一并删掉。TO-DO Panel 的目标，是让“下一步做什么”“任务属于哪个项目”和“哪些产物可以安全清理”出现在同一条工作流里，同时尽量不打断当前操作。

## 初始产品要求

| 用户需求 | 产品要求 | 当前实现 |
|---|---|---|
| 平时不要被悬浮条挡住桌面 | 主窗口默认隐藏，按意图唤醒 | `main.js` 创建隐藏窗口 |
| 鼠标经过屏幕顶部不能误弹 | 仅在顶部中央约 `140 × 6 px` 停留至少 `350 ms`，且桌面空闲、没有按键时唤醒 | `main.js` 光标轮询与 `scripts/desktop-guard.exe` |
| 拖文件、选中文字、写代码时不能被打断 | 鼠标按键按下或非桌面前台时取消唤醒 | 主进程结合原生守护器过滤 |
| 任务要和正在做的项目放在一起 | 项目、今日任务、本周成果与开源雷达组成三栏工作台 | `renderer/index.html`、`renderer/app.js`、`renderer/styles.css` |
| AI 生成任务后不想再手动复制 | CLI 接受普通参数、JSON 和文件载荷，支持项目、路径、方案备忘与子任务 | `scripts/add-task.js`；主进程监听本地 store 变化 |
| 清理空间时不能误删关键版本 | 扫描并分类候选，保护识别出的稳定版与最新版；由用户选择后送入回收站 | `cleaner.js`、`main.js` 清理 IPC、渲染层审查浮窗 |
| 清理缓存不能把项目从知识库同步回来 | 只有清理成功且状态保存后，才从活跃列表移出项目和未完成任务，并记录删除编码 | `renderer/app.js` `autoRemoveWorkspaceProject()` |
| 关闭启动终端后工作台还要可用 | 由 WMI 独立启动并驻留系统托盘 | `scripts/launch-background.js`、`scripts/start-background.ps1` |
| 想在日常复盘时发现新的开发工具 | 提供手动和每日 20:30 的 GitHub 雷达刷新入口 | `main.js` GitHub API handlers、`renderer/app.js` 复盘与雷达流程 |

## 项目自己的差异点

### 1. 不是常驻悬浮窗，而是“意图唤醒”

常态完全隐藏；把鼠标放到精确的顶部感应区并停顿，且处于桌面、没有拖拽时才出现。这个交互把“随时可用”和“不遮挡、不误触”放进同一个设计目标。

### 2. Agent 是任务入口，不是旁边的聊天框

Agent 可通过 `scripts/add-task.js --json` 一次提交任务、项目代号、方案备忘和子任务。Electron 主进程轮询监听 store 文件，检测到外部更新后通知当前界面；Agent 不必直接操作 Electron UI。

### 3. 清理器理解“版本族群”

清理器把模型权重、安装包、固件和备份快照按族群分析，并保护识别出的稳定版和最新版。它把风险显式呈现给用户，再将选中项移入回收站。清理目标是可重建的中间产物；项目源码目录不会因此被删除。

### 4. 项目上下文来自真实工作目录

项目卡片可连接实际代码仓库与工作区路径，清理授权也以已登记根目录为边界。Obsidian 用来同步项目元信息，文件操作针对登记的真实工作区，而不是笔记文件本身。

### 5. 把复盘和开源发现放进工作台

每日复盘入口可以刷新 GitHub 仓库雷达；雷达卡片提供项目简介和追踪入口，选中的条目可直接转成待办。

## 设计约束与非目标

- 当前目标平台是 Windows；顶部唤醒依赖 Windows 桌面状态和原生守护器。
- “清理项目”指从应用的活跃列表移出项目与关联未完成任务；它不会删除项目源码目录。
- 仓库目前把个人工作区路径写在代码中。将这些路径移入用户配置，是重要的可移植性改进方向。
- `scripts/desktop-guard.exe` 有二进制文件，但仓库目前没有配套 C# 源码和构建工程；修改底层唤醒逻辑前需要先补齐可构建源文件。
- 本地 store 可能含个人路径与 GitHub Token，必须留在 Git 忽略的 `data/` 目录中。
- 当前冒烟命令只覆盖轻量启动，不代表清理、安全边界或整套 UI 交互已经通过自动化验收。

## 最适合展示的 30 秒体验

1. 把鼠标移到屏幕顶部中央并停住，工作台出现；在代码编辑器里做同样动作则不会弹出。
2. 从命令行或 Agent 发送一个带项目和子任务的 JSON，任务出现在今日主线中。
3. 打开项目清理审查，看到中间版本与受保护版本的区别，再将选中缓存送进回收站。
4. 打开 GitHub 雷达，选一个工具并直接追踪为任务。

这段体验展示的是本项目的核心主张：少打断、知道上下文、能被 Agent 操作、清理前先保护数据。
